# 判断点清单：从"感知"到"说出口"

> 用户要"越详细越好"。这份把**每一处会做判断的闸**按链路顺序列出来：
> 在哪个文件、什么条件、命中后发生什么、它想避免哪种事故。
>
> 每一条都来自真实代码（函数名/变量名可搜），不是设计意图。

---

## 一、总览：一次对话会过多少道闸

```
用户一句话
  │
  ├─ ᴾ¹ 要不要做"感知"        _perception_skippable()      → 省一次模型调用
  ├─ ᴾ² 感知到什么            perception.perceive()        → meaning/direction
  ├─ ᴾ³ 是不是把提示词吐回来   perception.looks_like_echo() → 当作没感知
  ├─ ᴾ⁴ 要不要睡              perception.decide_sleep()     → 只认它自己写的那栏
  │
  ├─ ᴹ¹ 要不要用长期记忆       memory_gate.judge()          → 不用就省上下文
  ├─ ᴹ² 召回来的记忆有没有实词重合（本轮新增）_spirit_recall() → 无关就不注
  │
  ├─ ᶜ¹ 回答里有没有编造       answer_gate.extract_claims()  → 逐条对账
  ├─ ᶜ² 要不要换一颗火种复核    dual_check.is_risky()         → 高危才双检
  ├─ ᶜ³ 证据够不够             proof_panel.collect()         → 面板展示
  ├─ ᶜ⁴ 该不该自审             self_audit.inspect()          → 出卡
  │
  ├─ ᴱ¹ 现在的心气/精力        inner / energy / interoceptive → 影响语气长短
  ├─ ᴱ² 对这个人什么印象       feeling_memory / relation      → 影响称呼温度
  │
  └─ 说出去之前：
      ├─ ᴿ¹ 硬伤闸（旁白/提示词回显/markdown/括号/前缀） human_gate.hard_flaws()
      ├─ ᴿ² 像不像人打分（B站评论）                      _human_score() ≥70
      ├─ ᴿ³ 是不是复读对方原话                            _clean_reply()
      ├─ ᴿ⁴ 是不是复读自己上一句                          _too_similar() ≥0.8
      ├─ ᴿ⁵ 是不是跑题                                    _topic_drift()
      ├─ ᴿ⁶ 消息签名/去重（前端）                          oneSig() / dedupeMsgs()
      └─ ᴿ⁷ 要不要真发（写操作）                          force 闸
```

## 二、感知层（⓪）的判断点

### ᴾ¹ `_perception_skippable(text)` —— 这轮**不用**问模型"感知"

`xiaojiao_app.py:2402`。**宁严不宽**，命中才省：

| 条件 | 说明 |
|---|---|
| 创作类（`_is_creative_writing`） | 写小说/续写，语义本身就明确 |
| 明确任务（`帮我/请你/麻烦/给我` + `分析/看/读/检查/改/写/查/整理/解释`），且**不含**"为什么/如何/是不是因为" | 要做什么很明确，不需再感知 |
| 长度 ≤ 24 字 **且** 命中：纯问候/致谢、问日期时间、问 IP/天气、纯数字比较、抓取指令 | 原话本身就是最好的检索词 |

**为什么要有**：一轮最少 3 次模型调用（感知/自评/回答），本机每次 2~6 秒，"你好"要等 18 秒。
**代价**：这几类句子不会留下"它觉得这意味着什么"的感知记录（日志里会写明用规则代替）。

### ᴾ² `perception.perceive(event, llm_fn, ...)` —— 感知一次

返回 `{meaning, touches_life, direction, raw, parsed_by, ok}`。

关键设计：**载体不把 meaning 解析成词表**。
`direction` 只认它自己写的「向：威胁/新的/好的/失去/无」；挑不出来就是空串。
`ok=False` 时调用方**不起心**（不拿规则兜底）—— 避免"载体替它感觉"。

### ᴾ³ `perception.looks_like_echo(raw)` —— 这是不是把提示词吐回来了

纯规则：`_ECHO_MARKS` 命中 **≥2 个** 即判回声。命中 → 当作没感知（`ok=False`）。

### ᴾ⁴ `perception.decide_sleep()` —— 要不要睡

**只认它自己写下的那栏**「睡：要 / 睡：不要」；没写清楚 = 不睡。

> 这里有一段被明确废弃的旧逻辑：载体给一个精力数字 → 收它一句话 → **在里面查关键词**
> （"累/休息/睡"）。实测两个都错：「我有点累，但还能继续」被睡了；「想歇一会儿」反而不睡。
> 结论写在代码注释里：**睡不睡该由它决定，不该由载体读判据。**

## 三、脑与记忆（①）的判断点

### ᴹ¹ `memory_gate.judge()` —— 这轮要不要动用长期记忆

`memory_gate.py`：`is_memory_question()` 先判"这是不是在问记忆"，再由 `judge()` 决定。
不用 → 省掉检索与注入的上下文。

### ᴹ² `_spirit_recall()` —— 召回的记忆**够不够相关**（本轮新增）

`xiaojiao_app.py`。两道闸：问题与认知**共享 ≥2 个 ≥2 字实词**，或相似度 **≥0.78**；否则一条都不注。

**为什么要**：实测这份嵌入对任何两句都给 0.62~0.82（"下班回家先做什么" 召回 "用户住在菏泽"，0.661）。
不加这道闸，无关记忆会把本来答对的题带偏（实测 1 好 3 平 **1 差**）。

### ᴹ³ `spirit_memory.remember()` —— 写入前的自校验（本轮新增）

| 条件 | 结果 |
|---|---|
| 有真实来源（工具/网页/用户） | `basis=external, verified=True` |
| 无来源，但句子里有**可证伪事实**（年份/百分比/元/条/次/版本号） | **拒收** |
| 无来源、无具体事实 | 收下，`basis=self` |
| 与已有记录相似度 ≥0.92 **且**共享 ≥3 个实词 | 判同题，不重复存 |

> 同类还有一个历史坑：阈值原来是 **0.6**，而无关句子相似度 0.75+ → **永远判同题**，
> 记忆库长期不增长（这是"学习有效性 1 好 3 平 1 差"的真因）。

## 四、元认知（③）的判断点

| 判断点 | 文件 | 条件 → 动作 |
|---|---|---|
| ᶜ¹ 有没有编造 | `answer_gate.extract_claims()` | 抽出断言逐条对账；`is_creative()` 时放行（创作不算编造） |
| ᶜ² 要不要换火种复核 | `dual_check.is_risky()` | 高危问题才双检；`_pick_reviewer()` 选一颗不同于原火种的模型 |

| ᶜ⁴ 该不该自审 | `self_audit.inspect()` | 有可查问题时出卡；`_tried_recently()` 防重复自审 |

## 五、情绪与状态（④）的判断点

| 判断点 | 文件 | 影响 |
|---|---|---|
| 精力够不够 | `energy.level()` / `is_sleeping()` | 决定回不回、回多长 |
| 内感受偏差 | `interoceptive.sample()` / `deviation()` | 决定"这次感觉不对劲" |
| 对这人什么印象 | `feeling_memory` / `relation` | 决定称呼温度 |
| 现实线 vs 念头线 | `dual_thread.state()` | 决定"该说现实的事还是走神" |
| 状态→硬改规则 | `perspective.policy()` | `drop_tools` / `front_tools` / `no_browse` / 语气档 |

## 六、表达前的判断点（最关键的一串）

### ᴿ¹ `human_gate.hard_flaws(t)` —— 结构性硬伤（**四条说话路径共用**）

命中任一条 → 这条**不发**：

| 硬伤 | 例子 |
|---|---|
| 提示词回显 | `视频里讲了什么：`、`他说：`、`标题：` |
| 旁白 | `说罢`、`你随口`、`顿了顿`、`眼睛还` |
| markdown | `**`、`##`、```` ``` ```` |
| 括号自我说明 | `（他抬杠）` |
| 说话人前缀 | `你：`、`回复某某：` |
| 多行 | ≥3 个换行（群里发大段像刷屏） |

接入点：`friends._clean_reply` · `ai_group._clean_group_text` · `moments.compose` · B站评论。

### ᴿ² `_human_score(t)` —— 像不像人（0~100，**只用于 B站 评论**）

- ≥70 → 采用
- <70 → 带原因重写，**最多 6 次**
- 6 次里最高 <50 → 放弃这条（不发）

为什么只有 B站 用：那边可以重试（后台），群聊/好友不能为一句回复反复调模型。

### ᴿ³ 复读对方原话（好友）

`friends._clean_reply`：`s.startswith(last_user)` 且 `len(last_user) ≥ 3` → 拒。
短语气词（"嗯"）允许后面用逗号自然接。

### ᴿ⁴ 复读自己上一句（好友）

`_too_similar(a, b)`：字符集重叠 **≥0.8** 判复读 → 要求换说法；还重复就**不发**。

### ᴿ⁵ 跑题（群聊）

`ai_group._topic_drift(text, topic)`：双字滑窗与群主题**无重合** → 只进日志、不进消息。
（剧本群 `mode=roleplay` 豁免。）

### ᴿ⁶ 去重与渲染（前端）

`oneSig()` 优先用 id 做签名；`dedupeMsgs()` 按 id 去重。
> 历史坑：签名原来不含 id，连发同一句时同一条被画两遍。

### ᴿ⁷ 真发之前（写操作）

`bili_reply` / `bili_send_message` / `run_command` 等：
**不传 `force` 一律拒绝**。自动评论、自动私信默认关。

## 七、按"想避免的事故"倒排

| 事故 | 是哪道闸在防 |
|---|---|
| 它把提示词当正文发出去 | ᴿ¹（提示词回显）· ᴾ³（回声） |
| 它写成小说/旁白 | ᴿ¹（旁白）· ᴿ²（重写） |
| 它复读你或复读自己 | ᴿ³ · ᴿ⁴ |
| 它发与视频无关的评论 | 先取字幕（`_video_digest`），取不到就不发 · ᴿ² |
| 群里越聊越偏 | ᴿ⁵ |
| 它拿无关记忆把答案带偏 | ᴹ² |
| 它把编的东西当认知存下来 | ᴹ³ |
| 它没经你同意就发评论/私信 | ᴿ⁷ |
| 它假装"我感知过了" | ᴾ² 的 `ok=False` → 不起心（不兜底） |
| 它被载体替它做决定（睡不睡） | ᴾ⁴ 只认它自己写的那栏 |

## 八、诚实的边界

- 这套清单是**静态的**：证明"有这道闸"，不证明"每次都走到"。
- ᴾ¹ 的跳过规则会让部分句子**没有感知记录**（日志会写明）。
- ᴿ² 只在 B站 评论用；其余三处只有硬伤闸，**不重写**。
- 打分器（`_human_score`/`human_gate.score`）是**规则**，不是模型判断——它能挡住结构性问题，挡不住"这句话很无聊"。
