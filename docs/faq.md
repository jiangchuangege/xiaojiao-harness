# 常见问题

## 它怎么自称 Qwen？

这是正常的。小焦的"大脑"默认是 Qwen 的权重，小焦是自己套在它外面的一层壳（人设 + 工具 + 记忆）。所以**连裸模型是 Qwen，连小焦的 `/v1` 或网页才是小焦**。想用小焦人格，就走 `/v1` 或网页。

## 能换成别的模型吗？

能。设置 → 模型管理 → 添加任一 OpenAI 兼容模型，人格和工具照常用。

## 工具不执行 / 不干活？

- 检查右上角「🛠️ 工具」是不是绿色（开）。
- 让它做的是"执行类操作"（建文件/写文件/跑命令），不是纯聊天。
- 聊天大脑（llama-swap:9292）得在跑。

## 刷新会话没了？

不会。已持久化，左边点会话就能切回去。

## 让它建文件，结果建错了名？

改成 `brain.engine` 保持 `auto`，人设里有"严格用你指定的文件名"这条。若还错，重开一下大模型。

## 报 CUDA OOM？

改 `xiaojiao_control.json` 的 `brain.llama.ctx`（32768 → 16384）。

## 云端 API 明明填对了，却一直报 `Invalid token` / 模型调用出错？

**先别急着改配置 —— 大概率不是你的问题。** 实测某家网关（Agnes）会出现"同一个 Key、
同一个请求，忽好忽坏"：连打 10 次 `GET /v1/models` 只有 3 次 200，其余全是
`401 Invalid token`；`POST /v1/chat/completions` 连打 10 次**全 401**。

怎么判断是哪一边的问题（把下面 4 条对一遍）：

| 现象 | 结论 |
| --- | --- |
| `GET /v1/models` 偶尔能 200（还能列出模型清单） | Key **是通的**，令牌校验在你账号上没问题 |
| `POST /v1/chat/completions` 一直 401 | 网关在**拒签聊天请求**（服务商侧：额度/密钥状态/风控/故障） |
| Key 里没有空格/换行/不可见字符，`base_url` 也正确 | 不是粘贴问题 |
| 换台网络/换个时间仍 401 | 不是你本地环境的问题 |

小焦这边的处理（都不用你管）：

1. **自动重试**：401/403/429/5xx 会按 0.7s → 1.4s → 2.1s 退避重试 4 次，偶发拒签能救回来。
2. **自动兜底**：重试仍失败 → 自动改用**本地大脑**回答，并在回答末尾如实标注
   「本次回答由本地大脑完成 + 真实原因 + 最近 N 次成功 K 次」。
3. **不糊 JSON**：错误会被收拾成人话（`HTTP 401 · API Key 无效或已过期（服务端说：Invalid token）`）。

你该做的：登录服务商控制台看**密钥状态/额度**是否正常；若显示正常，就是对方网关的问题，
过一会儿或换个模型再试。期间小焦用本地大脑照常工作（实测本地模型 0.5～8 秒出结果）。

## 怎么让它更聪明？

换更壮的底座模型，或加大 `ctx`。人格/工具/记忆这套壳不用动。
