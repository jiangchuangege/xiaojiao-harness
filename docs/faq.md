# 常见问题

## 它怎么自称 Qwen？

这是正常的。小焦的"大脑"默认是 Qwen 的权重，小焦是自己套在它外面的一层壳（人设 + 工具 + 记忆）。所以**连裸模型是 Qwen，连小焦的 `/v1` 或网页才是小焦**。想用小焦人格，就走 `/v1` 或网页。

## 能换成别的模型吗？

能。设置 → 模型管理 → 添加任一 OpenAI 兼容模型，人格和工具照常用。

## 工具不执行 / 不干活？

- 检查右上角「🛠️ 工具」是不是绿色（开）。
- 让它做的是"执行类操作"（建文件/写文件/跑命令），不是纯聊天。
- 聊天大脑（llama-swap:9292）得在跑。

## 刷新会话没了？

不会。已持久化，左边点会话就能切回去。

## 让它建文件，结果建错了名？

改成 `brain.engine` 保持 `auto`，人设里有"严格用你指定的文件名"这条。若还错，重开一下大模型。

## 报 CUDA OOM？

改 `xiaojiao_control.json` 的 `brain.llama.ctx`（32768 → 16384）。

## 云端 API 明明填对了，却一直报 `Invalid token` / 模型调用出错？

**先别瞎改配置，用体检工具定位。** 一条命令：

```powershell
python tools/check_cloud_brain.py              # 体检当前配置
python tools/check_cloud_brain.py --key sk-xxx # 临时测另一把 Key（不写配置）
```

它会给结论（判据**只看 `POST /v1/chat/completions` 能不能通**）：

| 体检结果 | 含义 | 怎么办 |
| --- | --- | --- |
| chat 全通 | 配置没问题 | 不用管 |
| chat 时通时不通 | 网关偶发拒签（服务商侧抖动） | 小焦已内置退避重试 + 本地大脑兜底，等一会儿再试 |
| **chat 一次都没通** | **这把 Key 在服务商那边没被接受** | 见下面 4 条 |

> ⚠️ **别拿 `GET /v1/models` 当证据**：实测连「空 Key」「乱写的 Key」都能时不时拿到 200
> （网关/缓存有时候不校验令牌）。所以"models 能通"**不等于**"Key 是对的"——
> 这个坑我自己踩过：曾据此告诉用户"你的 Key 是对的"，是错的。

chat 一次都没通时，按顺序排：

1. **这把 Key ≠ 你其它客户端里能用的那把**（最常见：复制到了旧 Key、少了几位、屏幕截图里的）。 
   最快验证：`python tools/check_cloud_brain.py --key <你确认能用的那把>`
2. 该 Key 已失效 / 被停用，或额度用完。
3. 账号需要在服务商控制台激活该模型或子账号权限。
4. 对方网关故障 —— 把体检输出的 **request id** 报给服务商支持确认。

小焦这边的自动处理（不用你管）：

1. **退避重试**：401/403/429/5xx 按 0.7s → 1.4s → 2.1s 重试 4 次。
2. **自动兜底**：仍不通就改用**本地大脑**回答，并在回答末尾注明「本次由本地大脑完成 +
   真实原因 + 最近 N 次成功 K 次」。
3. **不糊 JSON**：错误收拾成人话（`HTTP 401 · API Key 无效或已过期（服务端说：Invalid token）`）。

> 官方排查清单（base_url、Bearer 格式、401/429 含义）见 Agnes 的
> [TROUBLESHOOTING](https://github.com/AgnesAI-Labs/AgnesAI-Models/blob/main/docs/TROUBLESHOOTING.md)。

## 怎么让它更聪明？

换更壮的底座模型，或加大 `ctx`。人格/工具/记忆这套壳不用动。
