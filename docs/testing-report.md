## 4. 稳定性

### 已做的等效抽样
- **连续 20 次调用**：Python 堆净增 **0.10MB**（无泄漏迹象），20/20 成功。
- **熔断 + 自愈**：失败 3 次触发，**32 秒后自动恢复**（不是永久禁用）。
- **会话回收**：TTL/空闲/LRU 三规则生效，**浏览器会话不会无限堆积**。
- **5 并发**：无崩溃、无数据串扰。

### 24 小时长跑（脚本已备，需你在长跑环境执行）
```powershell
python tests/stress/stability_24h.py --hours 24 --per-round 10 --interval 3600
```
- 每小时抓 10 个 URL，记录：成功率、P95 延迟、Python 堆增长、异常/崩溃
- 结束输出 `stability_report.json` + Markdown 摘要，并对"P95 是否衰减/堆是否持续增长"给出结论
- **本轮未执行真 24 小时**（受会话时长限制）—— 这是**已知缺口**，不假装做过

## 6. 结论与后续

**结论**：抓取插件与安全闸门已达"可交付"水平（94/94、无高危未修项）；
**全项目**（视频/播客/音乐/安装器/小脑训练）的自动化覆盖仍不完整，属"可运行但未完全自动化"。

**建议优先级**：
1. 给小脑推理与记忆检索补最小单测（改动最频繁、回归代价最高）。
2. 用 Playwright 给前端渲染加真实断言（现成的浏览器依赖已在抓取插件里）。
3. 安装器加 `--dry-run` 模式后纳入 CI。
4. 在长跑环境执行 24 小时稳定性脚本，把结果写回本报告。
